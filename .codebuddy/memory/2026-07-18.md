## 修复「signal is aborted without reason」报错
- 用户反馈生成回复时卡片顶部报错：`错误：signal is aborted without reason`。

- 修复：
  - `services/siliconflow.js` 新增 `isAbortError()`：除 `err.name === 'AbortError'` 外，还检查 `err.code` 以及 message 是否包含 `aborted` / `signal` / `abort` 等关键字。
  - `controller.abort()` 传入显式 reason（`new Error('TIMEOUT')`），便于调试和识别。
  - catch 分支改用 `isAbortError(err)` 判断，统一返回 `TIMEOUT` 错误码，UI 会显示本地化文案「请求超时，请稍后重试。」。
- 验证：JS 括号平衡、siliconflow.js lint 0 错误。

## 修复「Extension context invalidated」报错
- 用户截图显示点击生成后报错：`[ReplyPilot] storage.getAll failed Error: Extension context invalidated.`。

- 修复：
  - `utils/storage.js`：新增 `isContextInvalidatedError()` 判断 error message 是否包含 `extension context invalidated`；在 `getAll()` 捕获同步异常时，若是上下文失效则返回 `CONTEXT_INVALIDATED` 错误码的 rejected Promise，而不是打印错误并回退默认值。
  - `content/reply-ui.js`：`ERROR_KEYS` 增加 `CONTEXT_INVALIDATED: 'errContextInvalidated'`。
  - `_locales/zh_CN`/`_locales/en`：新增 `errContextInvalidated`（中文「扩展上下文已失效，请刷新页面后重试。」/ 英文「Extension context expired. Please refresh the page and try again.」）。
- 验证：JSON 合法、JS 括号平衡、`storage.js` / `reply-ui.js` lint 0 错误。
- 说明：遇到该提示只需刷新 Gmail 页面即可；这是 Chrome 扩展 MV3 的正常行为，不是代码 bug。
