## ReplyPilot Gmail 弹窗「网络错误」根因与修复
- 现象：options 页「测试连接」成功，但 Gmail 弹窗点「生成回复」显示网络错误。
- 根因：options 页 origin 是 `chrome-extension://`，直接 fetch 外部 API 不受页面 CSP 限制；Gmail 弹窗的 chat() 在 content script 内以 `https://mail.google.com/` 运行，Gmail 页面 CSP 的 `connect-src` 拦截了直接 fetch，请求未出浏览器即失败，被包装成「NETWORK_ERROR」。
- 修复：新增 background 消息 `RP_FETCH_CHAT`（`background/service-worker.js` 的 `relayChatRequest`），由 service worker（origin chrome-extension://）转发 `POST /v1/chat/completions`；`services/siliconflow.js` 的 `chat()` 改为 `chrome.runtime.sendMessage({type:'RP_FETCH_CHAT', payload})` 转发，并在回调里按 status 映射 401/404/429/其他错误码。`testConnection()` 保持直接 fetch 不变（仅 options 用）。
- 验证：`node --check` 两文件通过、lint 0 错。
- 注意：Chrome 扩展项目未主动 push；改 background + services 后用户需 Reload 扩展。

## ReplyPilot NVIDIA 404 误判与错误提示布局修复 (commit 766b37a)
- 现象：用户填 endpoint `https://integrate.api.nvidia.com/v1` + model `minimaxai/minimax-m3`，Gmail 弹窗报「模型不存在 (404)」；错误提示挤在 header pill 里影响布局。
- 根因：用户填写的是 OpenAI 兼容 base URL，但 `services/siliconflow.js` 的 `chat()` 直接用该 URL 发 POST，请求实际打到 `https://integrate.api.nvidia.com/v1`（无 `/chat/completions` 路由），NVIDIA 返回 404，代码映射为 MODEL_NOT_FOUND。同时长错误文本放在 `.rp-card-status` pill 里会撑破 header。
- 修复：
  - `services/siliconflow.js` 新增 `normalizeChatEndpoint()`，对缺失 `/chat/completions` 后缀的 endpoint 自动补齐；`chat()` 与 `testConnection()` 均使用 normalize 后的 URL。
  - `content/reply-ui.js` 在卡片 body 顶部新增 `.rp-error-banner`，错误状态时 header 只显示简短 `statusErrorShort`，详细错误显示在 banner 中。
  - `content/content.css` 定义 `.rp-error-banner` 样式（红底、圆角、自动换行）。
  - `_locales/en/messages.json` 与 `zh_CN/messages.json` 新增 `statusErrorShort`。
- 验证：`node --check` JS/JSON 通过、lint 0 错。
- 注意：未主动 push；用户需 Reload 扩展。

## ReplyPilot 回复选项 tooltip 被卡片遮挡修复 (commit 3ee0f5a)
- 现象：用户悬浮在回复选项上未看到 tooltip 浮层。
- 根因：`.rp-card` 的 `z-index` 为 `2147483640`，而 `.rp-option-tooltip` 的 `z-index` 为 `2147483600`，tooltip 低于卡片，被卡片自身遮挡。
- 修复：`content/content.css` 将 `.rp-option-tooltip` 的 `z-index` 提升到 `2147483646`（仍低于 32-bit int 上限），确保浮层显示在卡片之上。
- 验证：未主动 push；用户需 Reload 扩展后悬浮即可看到完整回复内容。
