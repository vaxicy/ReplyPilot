## ReplyPilot Gmail 弹窗「网络错误」根因与修复
- 现象：options 页「测试连接」成功，但 Gmail 弹窗点「生成回复」显示网络错误。
- 根因：options 页 origin 是 `chrome-extension://`，直接 fetch 外部 API 不受页面 CSP 限制；Gmail 弹窗的 chat() 在 content script 内以 `https://mail.google.com/` 运行，Gmail 页面 CSP 的 `connect-src` 拦截了直接 fetch，请求未出浏览器即失败，被包装成「NETWORK_ERROR」。
- 修复：新增 background 消息 `RP_FETCH_CHAT`（`background/service-worker.js` 的 `relayChatRequest`），由 service worker（origin chrome-extension://）转发 `POST /v1/chat/completions`；`services/siliconflow.js` 的 `chat()` 改为 `chrome.runtime.sendMessage({type:'RP_FETCH_CHAT', payload})` 转发，并在回调里按 status 映射 401/404/429/其他错误码。`testConnection()` 保持直接 fetch 不变（仅 options 用）。
- 验证：`node --check` 两文件通过、lint 0 错。
- 注意：Chrome 扩展项目未主动 push；改 background + services 后用户需 Reload 扩展。

## ReplyPilot 每个引擎独立保存配置（per-provider config slots，commit 5229364）
- 用户痛点：切换 provider 时 apiKey/endpoint/model 不保留，每次切回 custom 都看到旧值要重填。
- 根因：原结构扁平存 `rp_apiEndpoint/rp_apiKey/rp_model` 各一份，切 provider 只覆盖成新预设，旧 provider 配置丢失。
- 改动：
  - `utils/storage.js`：DEFAULTS 新增 `rp_providerConfigs: {}`；`getAll()` 调用 `migrateProviderConfigs()` 自动把现有扁平字段按当前 `rp_provider` 搬进 `rp_providerConfigs[provider]`（老用户升级不丢配置，幂等）。
  - `services/ai-service.js`：新增 `resolveProviderConfig(s)` 从 `s.rp_providerConfigs[s.rp_provider]` 取 endpoint/key/model，slot 为空时回退扁平字段；generateReply/generateOptions/refineReply 三处 chat 调用改用 `cfg.*`。
  - `options/options.js`：重写 `loadSettings`（按当前 provider 的 slot 填表）、`applyProviderSlot`（切 provider 时先存旧 slot 再读新 slot，无 slot 则回落预设）、`saveSettings`（把当前输入写入 `rp_providerConfigs[currentProvider]`，同时同步扁平字段兼容）；provider change 事件先存旧 slot 再切新 slot。
  - `popup/popup.js`：状态徽章按当前 provider 的 slot key 判断已配置。
- 效果：siliconflow / openai / custom 三套配置互不覆盖，切回即显示各自保存的 key/地址/模型。
- 验证：`node --check` 四 JS 全通过、lint 0 错。未主动 push；用户需 Reload 扩展生效。

## ReplyPilot 切回自定义引擎配置被清空修复
- 现象：每次切到「自定义 (OpenAI 兼容)」时，Base URL / API Key / 模型 ID 被刷新成空，不保留上次填写的记录。
- 根因：`options/options.js` 的 `saveSettings()` 里写 `obj.rp_providerConfigs = {}`，每次保存都会把整个对象替换掉，只保留当前 provider 的 slot；切到其它 provider 时，旧 provider 的 slot 被整体覆盖丢失，再切回来只能回落空预设。
- 修复：
  - `saveSettings(silent, baseSettings)` 改为先读取（或接收传入的）现有 `rp_providerConfigs`，只覆盖当前 provider 的 slot，保留其它 provider 的 slot。
  - provider `<select>` 的 change 事件把内存中已合并的 `settings` 传给 `saveSettings(true, settings)`，确保切换前刚改但未 autosave 的旧 provider 值也被保留。
- 验证：`node --check options/options.js` 通过，lint 0 错。
- 注意：未主动 push；用户需在 chrome://extensions 点 Reload 扩展生效。
